# Выбор и настройка мониторинга в системе
## Мотивация:
Необходимо отслеживать сбои в системе и успевать на них реагировать раньше, чем получим отзывы клиентов: мы теряем слишком большое количество денег из-за того, что не реагируем вовремя.

## Выбор подхода к мониторингу:

Для MES API: четыре золотых сигнала
Для Shop: бизнес-метрики 
Для CRM: бизнес-метрики
Для RabbitMQ: USE-метрики

## Метрики:
MES API:
- Latency — сколько времени занимает расчет (особенно если до 30 минут!). 
- Traffic — количество запросов на расчет (по API, от клиентов и от внутреннего магазина).
- Errors — доля фейловых расчетов, таймаутов, падений.
- Saturation — если очередь расчетов становится перегруженной, это видно по времени ожидания.

Цель: стабильность расчетов и прозрачность SLA
Ярлыки: client_type (B2C/B2B), model_complexity (low/medium/high)

Shop:
- Конверсия по этапам: INITIATED → FILE_UPLOADED → SUBMITTED.
- Доля пользователей, не завершивших заказ.
- Latency / Errors по API-запросам к ME.

Цель: определить узкие места в воронке продаж и плохой UX
Ярлыки: stage

CRM:
- Время между SUBMITTED → MANUFACTURING_APPROVED.
- Доля заказов без APPROVED за > 8 часов.
- Количество заказов в статусах MANUFACTURING_STARTED, но не COMPLETED.

Цель: определить количество "зависших" заказов и справляются ли менеджеры с текущей загрузкой.
Ярлыки: manager_id, model_complexity

RabbitMQ:
- Utilization: занятость ресурса.
- Saturation: перегрузка ресурса.
- Errors: количество ошибок.
  
- Message Count: количество сообщений в очереди.
- Dead Letter Queue: количество сообщений в DLQ.
- Процент сообщений с ошибкой: сколько сообщений не удалось обработать.
- Processing Time: время обработки сообщений

Цель: надежность передачи данных между системами
Ярлыки: queue_name

## План действий:
1. Установить Prometheus и Grafana.
2. Подключить экспортеры: RabbitMQ Exporter, Node Exporter (для инфраструктуры).
3. Встроить клиентские библиотеки Prometheus в Java и C# приложения (Shop, CRM, MES API).
4. Добавить ярлыки к метрикам
5. Создать дашборды в Grafana:
    - Дашборды для RabbitMQ: мониторинг очередей, сообщений, ошибок, времени обработки.
    - Дашборды для MES и Shop: метрики расчётов, конверсии, ошибок.
6. Настроить оповещения:
- В очереди RabbitMQ больше 100 сообщений
- Заказ остаётся в статусе SUBMITTED более 4 часов
- Время расчёта стоимости превышает 15 минут
- Ошибки 5xx по MES API за последние 10 минут выше 5%
